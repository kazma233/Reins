# 左侧会话列表改为轻索引 + 假分页

- 日期：2026-05-10
- 状态：已采用

## 背景

启动后左侧会话列表加载慢，主要问题不是前端渲染，而是列表首屏前就提前为整批会话构建完整摘要信息。

对 Codex / Claude 这类 JSONL 来源，完整摘要需要读取会话内容才能拿到标题、`cwd`、`gitBranch` 等字段。之前如果在列表索引阶段就把这些信息全量解析出来，启动首屏会被所有历史会话的扫描和解析拖慢。

## 决策

左侧会话列表不再在索引阶段为所有会话提前构建完整摘要，而是采用下面的策略：

1. 先构建轻索引，只保留列表排序和定位所需的最小信息。
2. 列表分页仍保留现有交互，但底层不是“真实分页查询”，而是“全量轻索引 + 当前页按需补摘要”的假分页。
3. 当前页需要展示的会话，才解析完整摘要信息。
4. 已解析过的单会话摘要进入缓存，翻页或回到上一页时直接复用。

## 当前边界

- Codex / Claude：
  列表索引阶段只提取 family 归属、路径、排序时间、最小 session 标识，不提前为整批会话解析标题和附加字段。
- OpenCode：
  仍然走当前的数据库索引逻辑，因为它的读取成本模型和 JSONL 来源不同。
- 详情页：
  仍按需加载，不和左侧列表首屏绑定。

## 结果

- 启动首屏只需要支付“轻索引 + 第一页摘要解析”的成本。
- 后续翻页会有单页摘要解析开销，但可以靠摘要缓存摊平。
- 这次优化优先保证首屏响应，而不是追求一次性把所有列表信息算完。
