# 会话从「左右分栏」改为「列表页 → 会话页」

- 日期：2026-10-15
- 状态：已采用

## 背景

会话浏览原先是左侧 320px 列表 + 右侧详情的同屏分栏。列表标题要两行截断才塞得进窄栏，
详情被压在剩下的宽度里；两者互相让位，谁都读不舒展。

## 决策

拆成两个整屏视图，由 `SessionWorkspace` 的 `view` 状态切换：

1. **列表页**：整屏宽度铺开，顶部**一行**放刷新、来源切换与筛选（搜索框 + 排序），列表自身
   滚动（页面不滚动）。内容列限宽 1200px 居中，超宽窗口上标题不会拉成一条长行。条目是标题一行
   （按需换行完整展示）+ 附加信息一行 flex（时间 / 模型 / 状态角标 / 使用量），窄窗口只换行。
   收窄窗口时顶栏整组换行，不挤字。
   - 来源检测期间的加载动画在**正文中心**（`.sessions-loading`），不再挂在顶栏；检测中不渲染
     列表，避免"该来源下暂无会话"和加载中同时出现让人以为已经加载完。
   - 标题的"完整"是**按字符数不再截断**（后端 `normalize_title` 去掉了 72 字符上限，摘要缓存
     v4 → v5 重建）；显示侧只保留行数上限（列表 4 行、详情标题 6 行），用来挡住把整段粘贴内容
     当标题的会话（实测存在 1.1 万字符的 HTTP 报文标题），全文仍在 tooltip 里。
2. **会话页**：点列表行进入，整屏展示该会话的概览、消息、事件与工具调用。页面顶部是**常驻顶栏**
   （`.detail-page__bar`，返回入口与正文列同宽同缩进），正文是它下面的滚动容器，滚到长会话底部
   返回入口也不会跟着滚走。正文列限宽 1000px——消息流与过程行的行尾控件在整宽屏幕上会离内容太远。
   时间线工具条（消息/raw/筛选/只看对话）吸顶在顶栏之下（`top: 0` 于滚动容器内，正好贴着顶栏下沿）。

## 会话列表 ↔ 用量统计

列表顶栏最右是「会话统计」入口，跳转到用量统计页（`appMode = "usage"`）；用量统计页标题上方有
「← 返回」（按钮文案就是两个字，`appMode = "sessions"`）。两者都只切 app mode，不复制对方状态。左栏不再单列
统计条目：入口与回程成对出现，不必再占一个常驻位。停在统计页时左栏把「历史会话」保持点亮
（`AppModeRail` 的 `activeMode`：usage 归到 sessions），否则整条栏没有任何选中项，看起来像坏了。

左栏底部固定一个「关于」入口，进的是整屏页（`appMode = "about"`，不是弹窗）。它是**左栏的顶层页**，
与配置与分发/模型配置/历史会话平级，所以页面内不放返回——换页由左栏承担；在关于页时左栏把「关于」
自己点亮。版本取自 `getVersion()`（tauri.conf.json 单一来源），工具名取自 `agent-labels.ts` 共享常量表。

只有"从别处钻进去的子页"才带返回入口：用量统计从会话列表进，所以它有「← 返回」。

子页的返回链接抽成 `@shared/ui/BackLink.vue`：用量统计页与关于页共用一份样式与箭头，改名改样式只改一处。

左栏本身从 48px 图标条改成 176px 窄列表：每行图标 + 名字，整行可点，窄屏下比只有图标的方按钮
更好认。

会话工作区在 `App.vue` 里用 `KeepAlive` 包住：来回切模式时搜索词、排序、已加载的后续页、当前是
列表还是会话页都保留（列表数据本身在 pinia store 里，保留的是本地视图状态）。其余模式维持原有的
卸载重建行为，所以统计区的数据仍是每次进入重新拉取。

**滚动位置要单独记**：KeepAlive 把视图移进隐藏容器时，子树没有布局盒，浏览器会把内部滚动位置清零，
且失活钩子里读到的已经是 0（DOM 先被移走，钩子后执行）。做法是
`composables/useKeepAliveScroll.ts`：各视图挂载时登记自己的滚动容器，`App.vue` 订阅
`appStore.$onAction`，在 `setAppMode` 真正执行前主动抓一次偏移（此时 DOM 还在文档里），视图激活时写回。
不依赖 `scroll` 事件——部分 webview 对程序化滚动不派发该事件，实测本机 IAB 里 `.content-panel`
滚动到 800 却没有收到任何 `scroll`（连 document 捕获阶段也没有）。

## 整屏页的留白与控件尺寸约定（以模型配置为参照）

三个模式页与两个会话子页共用同一套页面留白，改动前分别是 24/32（配置与分发）、18/24（历史会话）、
14/16（模型配置），肉眼可见不一致：

- 页面内容壳：`padding: 14px 16px 16px`（顶部 14、两侧 16、底部 16）。
- header 行内：横向由内容壳提供；header 与下方内容之间 12px + 分隔线，下方卡片/列表自带 16px。
- 不再给页面内容加居中限宽：模型配置页没有限宽，会话列表与详情原来各有 1200/1000 的上限，会让
  超宽窗口下的左留白和别的页对不上（详情页的时间线、顶栏返回按钮已同步去掉上限）。

数值来源：`src/features/providers/styles.css`（`.providers-content__header` 的 `14px 16px 12px`
与 `.providers-panel` 的 `16px`）；配置与分发生效的是文件末尾的 theme-flattening 块，改留白要改那里，
文件前部的同名规则会被它覆盖。

按钮高度收敛成三档，token 在 `src/styles.css`，新增按钮复用档位而不是再写一次性尺寸
（收敛前实测有 22 / 24 / 26 / 30 / 32 / 34 / 36 七种高度）：

| 档位 | token | 用途 |
| --- | --- | --- |
| 36px | `--button-height` | 页面级动作：刷新、会话统计、新增 Target、删除会话、应用提供商、左栏条目 |
| 32px | `--tab-height` | 标签页与分段控件：页面 tab（targets/skills/mcp、Agent/提供商）、消息/raw、只看对话、时间窗切换、会话页返回 |
| 28px | `--button-height-compact` | 行内小动作：移除、同步、编辑、卡片扩展按钮，以及时间线里的过程行 |

按钮文字也收成两套 token，不再各写一个字号字重（收敛前实测有 11 / 12 / 13px 三种字号、400 / 500 / 600
三种字重）：

| 用途 | token | 收敛后取值 |
| --- | --- | --- |
| 动作按钮（`--button-height` 档） | `--button-font-size` + `--button-font-weight-strong` | 13px / 600 |
| 标签、分段、左栏条目（`--tab-height` 档） | `--button-font-size` + `--button-font-weight` | 13px / 500 |
| 紧凑按钮与返回链接（`--button-height-compact` 档） | `--button-font-size-compact` + `--button-font-weight` | 12px / 500 |

时间线里的过程行是内容行（12px / 400），不按按钮排版。

`better-ui` 的另一条：悬停样式只在支持悬停的指针下生效。全仓 29 处 `:hover` 统一包进
`@media (hover: hover)`（触屏上 `:hover` 会在点按后粘住，读成"选中了"）。仅悬停可得的反馈不算反馈，
所以每处 hover 都另有常显的状态线索（颜色、图标或文案）。

输入类控件统一用 `--control-height`（36px）：文本 / 搜索输入框、下拉选择器、多选触发器都归它，
`size="sm"` 的小号变体（provider 弹窗里的模型元数据行）用 `--button-height-compact`（28px），
勾选行（`.providers-check`）同归紧凑档。写死的 30px、padding 撑出来的 ~32px 都已换掉。

内容型元素（会话卡片、过程行）虽然也是 `<button>`，但它们是被点的"行"，保留自身高度，不套档位。

## 保留的行为

- 选中态仍在 session store 里：返回列表时原行保持高亮，再次进入同一条会话直接用已加载的 overview，
  不重新拉取。
- 滚动加载仍在列表与时间线各自的容器里（`provide("sessionScrollContainer")` 指向会话页的滚动容器）。
- 删除会话后清空选中并回到列表，再刷新列表。
